🎬 Petunjuk Aksi Layar & Visual:
Beralih ke tampilan Code Editor (VS Code). Buka sidebar file explorer di sebelah kiri. Arahkan kursor dan buka folder-folder utama: app, routes, resources, database, public, bootstrap/app.php, dan berkas .env.
🗣️ Naskah Lisan Kata-per-Kata:
"Sekarang kita beralih ke poin kedua, yaitu Struktur Proyek Laravel.

Aplikasi ini dibangun menggunakan arsitektur modern Laravel 11/12 yang sangat bersih dan terorganisir. Mari kita bedah fungsi dari folder dan file intinya:

1. Folder app/: Merupakan jantung dari logika bisnis aplikasi. Di dalam subfolder Http/Controllers/ terdapat seluruh controller yang memproses permintaan HTTP, seperti ItemController, LoanController, ReturnLogController, dan ReportController. Di subfolder Models/ terdapat Eloquent ORM yang merepresentasikan tabel basis data. Serta terdapat Requests/ untuk validasi formulir dan Middleware/ untuk otorisasi hak akses.

2. Folder routes/: Berfungsi sebagai pemetaan URL aplikasi. File utama yang kita gunakan adalah routes/web.php yang mendefinisikan rute web berproteksi otentikasi dan peran admin, serta routes/auth.php yang menangani rute login, register, dan reset password dari Laravel Breeze.

3. Folder resources/: Berisi lapisan presentasi antarmuka. Di dalam resources/views/ terdapat file-file Blade template yang terbagi rapi ke dalam folder entitas seperti items/, loans/, categories/, reports/, dan folder layouts/ untuk master layout tampilan. Di sini juga terdapat css/ dan js/ yang dikompilasi oleh Vite.

4. Folder database/: Menyimpan struktur skema basis data. Subfolder migrations/ berisi file migrasi untuk version control tabel, serta seeders/ untuk menabur data awal pengujian sistem.

5. Folder public/: Merupakan satu-satunya document root yang dapat diakses publik oleh web server. Berisi index.php sebagai titik masuk aplikasi, asset hasil build Vite, gambar, dan dokumen statis.

6. File .env: Menyimpan konfigurasi variabel lingkungan yang bersifat sensitif dan dinamis, seperti koneksi database MySQL (DB_HOST, DB_DATABASE=inventaris_febi, DB_USERNAME), konfigurasi session, dan nama aplikasi.

Poin penting arsitektur: Pada Laravel 11/12 yang kami gunakan, konfigurasi middleware dan penanganan error tidak lagi menggunakan Kernel.php lama, melainkan disatukan secara elegan di berkas bootstrap/app.php."

3. Database, Tabel, Relasi, Migration, Model & Seeder 05:45 – 08:30

🎬 Petunjuk Aksi Layar & Visual:
Di VS Code, buka folder database/migrations/ dan tunjukkan file-file migrasi. Selanjutnya buka file Model app/Models/Item.php dan app/Models/Loan.php untuk menunjukkan metode relasi belongsTo dan hasMany. Jika memungkinkan, tampilkan diagram relasi atau struktur tabel di phpMyAdmin.
🗣️ Naskah Lisan Kata-per-Kata:
"Memasuki poin ketiga, yaitu Database dan Relasi Antar Tabel.

Sistem Inventaris Sekolah ini didukung oleh basis data relasional MySQL yang terdiri dari 6 tabel entitas utama yang saling terhubung untuk menjamin integritas data referensial:

1. Tabel users: Menyimpan data kredensial akun, nama lengkap, email, password terenkripsi bcrypt, serta kolom penentu peran yaitu role dengan nilai enum admin atau user.
2. Tabel categories: Pengelompokan jenis barang inventaris, seperti Laboratorium Komputer, Multimedia, Alat Olahraga, dan Sarpras Umum.
3. Tabel items: Menyimpan detail spesifik barang, mencakup category_id sebagai foreign key, code (kode inventaris unik/SKU), nama barang, sisa stock fisik, kondisi awal, dan lokasi penyimpanan.
4. Tabel loans: Mencatat seluruh transaksi peminjaman. Menghubungkan user_id (siapa yang meminjam), item_id (barang apa), jumlah unit yang dipinjam, loan_date, due_date, serta status peminjaman (dipinjam, terlambat, dikembalikan).
5. Tabel return_logs: Mencatat log verifikasi pengembalian barang, dengan relasi foreign key loan_id, waktu aktual pengembalian returned_at, kondisi fisik barang saat kembali, dan catatan petugas.
6. Tabel activity_logs: Tabel pencatatan jejak audit (audit trail) otomatis yang merekam user_id, tipe aksi (seperti tambah barang, hapus transaksi, login), dan keterangan detail perubahan."

Relasi Eloquent Antar Model (Object-Relational Mapping):

🗣️ Naskah Lisan Kata-per-Kata:
"Di tingkat model Eloquent, relasi antar tabel dipetakan secara sangat terstruktur:
  • Relasi One-to-Many antara Category dan Item: Satu kategori memiliki banyak barang ($this->hasMany(Item::class)), dan setiap barang merujuk pada satu kategori ($this->belongsTo(Category::class)).
  • Relasi One-to-Many antara User dan Loan, serta antara Item dan Loan: Pengguna dan barang dapat memiliki banyak riwayat transaksi peminjaman.
  • Relasi One-to-One antara Loan dan ReturnLog: Satu transaksi peminjaman hanya dapat memiliki satu catatan pengembalian resmi ($this->hasOne(ReturnLog::class)).
Selain itu, kami memanfaatkan Migration sebagai pengendali versi skema sehingga struktur tabel dapat dibuat ulang secara konsisten melalui perintah php artisan migrate. Kami juga menerapkan Database Seeder (seperti UserSeeder, CategorySeeder, dan ItemSeeder) yang menyediakan data awal yang siap uji coba, termasuk akun admin dan akun siswa pengujian."

4. Backend Laravel: Routing, Middleware, Validasi & Error Handling 08:30 – 11:00

🎬 Petunjuk Aksi Layar & Visual:
Di VS Code, buka berturut-turut: 1. routes/web.php (sorot middleware grouping). 2. app/Http/Middleware/EnsureUserRole.php (perlihatkan pengecekan peran). 3. app/Http/Requests/StoreLoanRequest.php (perlihatkan validasi kuota stok). 4. app/Http/Controllers/LoanController.php (sorot blok DB::transaction). 5. bootstrap/app.php (sorot exception handler CSRF 419).
🗣️ Naskah Lisan Kata-per-Kata:
"Kita lanjut ke poin keempat, yaitu Backend Laravel.

Di sisi backend, kami menerapkan praktik arsitektur terbaik untuk menjamin kecepatan, integritas data, dan keamanan aplikasi:

1. Routing & Pengelompokan Hak Akses:
Bisa kita lihat pada routes/web.php, semua rute sistem dibungkus di dalam middleware auth agar tidak dapat diakses tanpa login. Khusus untuk operasi manajerial seperti CRUD barang, kategori, pengguna, dan verifikasi pengembalian, rute diproteksi lebih lanjut menggunakan middleware khusus role:admin.

2. Middleware Kustom (EnsureUserRole.php):
Middleware ini bertugas memeriksa apakah pengguna yang sedang aktif memiliki peran yang diizinkan. Jika pengguna dengan peran 'user' atau siswa mencoba membobol URL admin melalui browser, sistem akan langsung menolak dan melempar respons HTTP 403 Forbidden: Akses Ditolak.

3. Validasi Form Request Ketat (StoreLoanRequest.php):
Validasi input tidak kami letakkan secara berantakan di dalam Controller, melainkan dipisahkan ke dalam Form Request khusus. Yang paling istimewa, selain aturan standar seperti format tanggal dan keharusan memilih barang, kami menambahkan aturan kustom menggunakan after-validation hook untuk memverifikasi bahwa jumlah unit yang dipinjam tidak boleh melebihi sisa stok fisik yang tersedia di database. Hal ini mencegah terjadinya stok minus.

4. Integritas Transaksi Database (DB::transaction):
Pada saat peminjaman dan pengembalian barang, terjadi dua operasi berantai: mengubah stok barang dan membuat log transaksi. Kami membungkus operasi ini di dalam DB::transaction(). Jika salah satu query gagal, database akan otomatis melakukan rollback utuh, sehingga tidak ada data menggantung atau stok yang tidak sinkron.

5. Penanganan Error yang Ramah Pengguna:
Pada bootstrap/app.php, kami mengkustomisasi penanganan TokenMismatchException (error CSRF 419) yang sering terjadi ketika pengguna membiarkan tab browser terbuka terlalu lama. Alih-alih menampilkan halaman error putih yang membingungkan, sistem secara otomatis mengalihkan pengguna kembali dengan notifikasi flash pesan yang informatif."

5. Frontend & Blade Templating Engine 11:00 – 13:00

🎬 Petunjuk Aksi Layar & Visual:
Di VS Code, buka file master layout resources/views/layouts/app.blade.php dan salah satu file view konten seperti resources/views/items/index.blade.php atau resources/views/dashboard.blade.php. Tunjukkan bagaimana data di-looping menggunakan @forelse dan diformat dengan aman.
🗣️ Naskah Lisan Kata-per-Kata:
"Berikutnya adalah poin kelima, yaitu Frontend dan Blade Templating.

Antarmuka pengguna SIM Sarpras dirancang dengan pendekatan clean, modern, and responsive menggunakan template engine bawaan Laravel, yaitu Blade, yang dipadukan dengan Tailwind CSS dan Alpine.js.

1. Konsep Layouting & Reusability:
Kami menerapkan prinsip DRY (Don't Repeat Yourself) dengan menggunakan master layout layouts/app.blade.php. Komponen seperti navbar atas, sidebar navigasi, modal konfirmasi, hingga penampil alert pesan flash disatukan dalam layout utama. Halaman-halaman konten seperti daftar barang dan form peminjaman cukup memanfaatkan tag komponen <x-app-layout> dan menyuntikkan konten ke dalam slot yang tersedia.

2. Proses Menampilkan Data dari Backend:
Data yang dikirimkan dari Controller—misalnya daftar barang yang sudah dipaginasi—diterima oleh view Blade dan ditampilkan menggunakan direktif @forelse. Direktif ini sangat rapi karena secara otomatis menangani kondisi ketika data ditemukan maupun ketika data masih kosong melalui blok @empty.

3. Keamanan Rendering & Sanitasi XSS:
Semua output teks dari pengguna dirender menggunakan kurung kurawal ganda {{ '{{ $item->name }}' }}. Laravel secara otomatis menjalankan fungsi htmlspecialchars() untuk menyaring karakter berbahaya, sehingga aplikasi kebal dari serangan Cross-Site Scripting (XSS).

4. Blade Directives untuk Personalisasi Antarmuka:
Kami menggunakan direktif @if(Auth::user()->isAdmin()) untuk menampilkan tombol aksi administratif—seperti tombol 'Tambah Barang', 'Edit', dan 'Hapus'—secara kondisional hanya kepada Admin. Bagi siswa, tombol-tombol tersebut disembunyikan sepenuhnya dari antarmuka.

5. CSS Cetak Responsif (@media print):
Pada halaman laporan dan bukti peminjaman, kami menyematkan aturan CSS khusus cetak. Saat tombol print ditekan, sidebar, header, dan elemen tombol aksi otomatis disembunyikan sehingga dokumen yang tercetak di atas kertas A4 terlihat resmi, bersih, dan profesional."

Dan untuk menguji keamanan otorisasi: jika siswa mencoba mengetikkan URL rahasia admin seperti /users secara langsung di address bar, middleware EnsureUserRole langsung mencegat dan menampilkan halaman 403 Akses Ditolak. Ini membuktikan sistem memiliki lapisan keamanan yang sangat andal."

🗣️ Naskah Lisan Kata-per-Kata:
"Memasuki poin ketujuh, yaitu Kendala dan Solusi.

Selama kurang lebih tiga minggu proses perancangan dan pengkodean, tentu saja saya menghadapi beberapa kendala teknis nyata. Namun dari kendala-kendala inilah pemahaman teknis saya berkembang pesat. Berikut adalah empat kendala utama beserta solusi yang saya temukan dan terapkan:

1. Kendala Sinkronisasi Stok & Potensi Race Condition:
Masalah: Jika ada beberapa pengguna mengajukan pinjaman terhadap barang yang sama pada waktu yang hampir bersamaan, berpotensi terjadi pembacaan stok lama yang menyebabkan stok fisik minus di bawah nol.
Solusi: Saya menerapkan dua lapis pertahanan: pertama, validasi Form Request kustom StoreLoanRequest yang memeriksa ketersediaan stok sebelum eksekusi; dan kedua, membungkus proses dekremen stok dan pembuatan baris pinjaman ke dalam DB::transaction() atomis.

2. Integritas Relasi Foreign Key saat Penghapusan Data:
Masalah: Saat Admin ingin menghapus data barang lama, database MySQL menolak dengan error Integrity Constraint Violation karena ID barang tersebut masih tercatat sebagai foreign key pada riwayat transaksi peminjaman lampau.
Solusi: Saya mengimplementasikan fitur Soft Deletes (trait SoftDeletes dan kolom deleted_at) pada tabel items dan loans. Dengan demikian, data barang dinonaktifkan dari katalog tanpa merusak atau menghilangkan integritas riwayat transaksi masa lalu.

3. Masalah Sesi Formulir Kedaluwarsa (CSRF Error 419):
Masalah: Ketika pengguna membuka tab form peminjaman lalu meninggalkannya beberapa saat, token CSRF kedaluwarsa sehingga saat tombol simpan ditekan muncul halaman putih error 419 Page Expired.
Solusi: Pada berkas bootstrap/app.php, saya mengonfigurasikan custom exception handler untuk menangkap TokenMismatchException, lalu secara otomatis mengalihkan pengguna kembali ke halaman form dengan pesan flash peringatan yang ramah dan meminta mereka mengirim ulang form.

4. Tata Letak Cetak Dokumen Fisik yang Berantakan:
Masalah: Pada awalnya, ketika fitur cetak laporan dibuka, seluruh elemen antarmuka web seperti navbar atas, tombol aksi, dan pagination ikut tercetak dan merusak format kertas A4.
Solusi: Saya menulis aturan stylesheet cetak terdedikasi menggunakan media query @media print. Aturan ini menyembunyikan elemen navigasi, menata ulang margin kertas A4, serta mengatur header kop resmi sekolah secara rapi."
